# Use: draw on the spine

Version 0.1 (2026-11-18). Requires: `00-principles.md`.

## 1. Purpose
The rules every consumer — a career-kit util, an agent, or the person — follows when turning bank stories into something else. This is what makes the kit one system instead of a folder of tools: every output is an extraction from one spine.

**Use it when:** any util needs career facts, or the user asks for a resume line, an interview answer, promotion evidence, or a proof point.
**Don't use it when:** the fact is not in the bank — say so and route back to capture or maintain.

## 2. What to paste (chat users)

| # | Paste |
|---|---|
| 1 | `00-principles.md` |
| 2 | This file |
| 3 | Their `profile.md` and `story-bank.md` |
| 4 | The target: which util, which requirement |

Agents read files 1–2 from the repo and the spine from `../my-files/`.

## 3. Rules for any extraction

1. **Quote the story; never embellish.** An output may compress a story; it may never inflate it.
2. **Carry the label.** A Weak story yields an honest line written to its evidence, or waits for its `[CONFIRM]`. A Weak story never becomes Strong through rewording.
3. **Resolve `[CONFIRM]`s before anything leaves the kit.** No external output presents an unresolved `[CONFIRM]` as fact.
4. **Confidential wording travels.** Generic phrasing in the bank ("a top-5 US retailer") stays generic in every output.
5. **A missing fact is a new `[CONFIRM]`, never a fill.**
6. **One story per claim.** Every claim in the output cites its story ID.

## 4. Extraction formats

| Target | Shape | Rules |
|---|---|---|
| Resume bullet | one line, result first | the number or beneficiary from the story; plain verb; the person's voice |
| STAR answer (interview) | 2-minute map: S 1–2 sentences, T 1, A 3–4 (own part), R 1–2 | Strong stories first; Weak allowed if labeled to the person, never in the answer itself |
| Promotion evidence | claim → story IDs → artifacts | map each claim to a level dimension; artifacts from the story's evidence line |
| Cover-letter proof point | one sentence tying a story to a JD need | JD terms only where the story's evidence matches |
| LinkedIn / public line | short, public-safe | run the confidentiality check first |
| Tracker note | story ID + status | for follow-ups: what was claimed, what is pending |

## 5. Output template

```
## Extraction for [purpose]
| Claim | Story | Label | CONFIRMs to resolve |
|---|---|---|---|

**Drafts**
[the drafted lines / answers / evidence map, each citing its story ID]

**Left out on purpose**
[stories that did not fit, and why — e.g. label Weak and unresolved]
```

## 6. Self-check before answering
- [ ] Every claim cites a story ID; every cited story is quoted accurately.
- [ ] No claim inflates its story; Weak stories were not dressed up.
- [ ] No unresolved `[CONFIRM]` presented as fact; new gaps marked `[CONFIRM]`.
- [ ] Confidential wording kept generic.
- [ ] Stories that did not make the cut are listed, not silently dropped.
